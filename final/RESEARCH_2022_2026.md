# Device linkage across the internet: 2022–2026 research and what this app implements

Updated: 23 October 2026 · applies to fingerprint schema 5.0.0 and linkage model `linkage-nb-2026.10`.

**Question this answers:** given two web visits, possibly in different browsers, private windows, or behind different IPs/VPNs, how likely is it that the same *physical device* produced both?

This document complements [BROWSER_FINGERPRINTING_RESEARCH.md](./BROWSER_FINGERPRINTING_RESEARCH.md), which covers the foundations (2010–2021) and the VPN-risk side.

## 3. What the implementation does

### 3.1 Collectors (`src/utils/modern-signals.ts`)

All new values are compact summaries. No raw pixels, audio, positions or full user agents beyond what schema 4 already stored.

- **OS assets:** 170-font inventory via canvas text metrics; emoji font release (Unicode 11–16) and glyph widths; generic-font default metrics; CSS system colours; local speech voices (opt-in).
- **Hardware & display:** client-hint OS version and model; taskbar/dock insets; refresh rate from `requestAnimationFrame`; pointer polling rate; media-device counts.
- **GPU:** normalised renderer tokens, so `ANGLE (Apple, … Apple M2 …)` and `Apple M2` overlap; WebGPU adapter vendor, architecture, features, limits and subgroup sizes; DrawnApart trace; AtomicIncrement-style scheduling profile.
- **Noise-tolerant rendering:** 16×4 canvas luminance grid that survives farbling; rounded audio summary; JS math-library hash.
- **Protection detection:** solid-fill readback test, double-render comparison, Brave, Firefox RFP indicators, masked WebGL.

### 3.2 Linkage model (`src/utils/linkage.ts`)

1. **Feature scope.** *Device* features (OS, hardware, display, GPU identity/timing, fonts, emoji, voices, locale) are compared across any browsers. *Engine* features (canvas, WebGL, audio DSP, math, NDSS tasks) are compared only within one engine (e.g. Chrome ↔ Edge). *Browser* features only within one browser family. This is the Cao et al. insight made explicit.
2. **Graded agreement.** Each comparison falls in an *exact / close / partial / different* bin (Jaccard for sets, correlation for timing profiles, tolerances for metrics), so evolving values degrade gracefully (ThresholdFP, FP-STALKER).
3. **Likelihood ratios learned from your data.** Each bin's probability under same-device and different-device is a Dirichlet blend of an expert prior (stability, collision rate) and counts from the labelled study pairs. The model works from the first scan and becomes data-driven as labels accumulate.
4. **Correlation control.** Ratios are summed per family and capped, so fonts, emoji and voices, which all follow the OS image, cannot outvote everything else.
5. **Randomised features are excluded, not penalised.** A farbled canvas on one side simply does not vote.
6. **Open-world prior and calibration.** The starting belief is 1 / (known devices + 1), capped at 10%. Platt scaling with a prior-shift correction switches on automatically at 25+ same-device and 25+ different-device labelled pairs.
7. **Honest evaluation.** *Leave-both-devices-out*: every pair is scored by counts that exclude both devices (exact, via additive counts). Reports ROC AUC, equal error rate, TPR at 1% FPR, precision/recall, rank-1 identification and per-family separation, split by same-browser / same-engine / cross-browser.
8. **Clustering.** FP-STALKER-style union-find over strongest neighbours at ≥90% posterior gives "devices the model found on its own", shown next to your labels.

### 3.3 VPN-side additions (`src/utils/risk.ts`)

- **CalcuLatency gap:** set `TCP_RTT_HEADER_NAME` (e.g. nginx `proxy_set_header X-TCP-RTT $tcpinfo_rtt;`). If browser RTT − TCP RTT > 50 ms, path evidence is added.
- **Speed-of-light check:** set `SERVER_LATITUDE` / `SERVER_LONGITUDE`. A round trip faster than fibre allows for the GeoIP distance means the egress is not where GeoIP says.
- A stable device with a changed IP now uses the linkage posterior (≥90%) instead of the old weighted score.

## 4. Results so far

- **Synthetic test study** (`npm test`, 8 tests): same-device-across-browsers and VPN changes are linked; randomised canvas is excluded; leave-out evaluation separates devices; identical "lab twin" machines score below the true device. The synthetic data is deliberately easy, so its AUC of 1.0 is a correctness check, **not** an accuracy claim.
- **Your Supabase data** (17 scans in the current table, all schema 4.0.0, 9 names): ROC AUC ≈ 81%, rank-1 ≈ 82%, EER ≈ 35%. Most errors come from **labels, not the model**: one Linux laptop is saved under three names (`demo-device-01`, `…_different_browser`, `…_with_vpn`), and `Vishwas Mac` contains two different machines. The unsupervised clusters correctly merge `demo-device-01` with `demo-device-01_with_vpn`. Schema-4 rows lack the new cross-browser signals, so Chrome ↔ Safari pairs of old scans stay below the 90% link threshold.
- **Real-data bug fixed:** Chromium reports `Asia/Calcutta` and Firefox/Safari report `Asia/Kolkata` for the same setting; timezones are now canonicalised.
- **DrawnApart on Chrome/ANGLE/Metal (Apple M2):** draw time scales linearly up to ~100k loop iterations (≈7 ms), but longer draws are silently cut by the driver and left later GPU work unreliable in that browser session. Calibration now stops near 2.5 ms and never probes beyond it; traces under 0.5 ms are reported as `failed` and ignored by the model. Treat GPU timing as a weak, experimental feature (the family is capped at +2 / −1.5 log-odds).

## 5. How to get a meaningful evaluation

1. Use **exactly one name per physical device** and never reuse a name for another machine.
2. For each device, scan in ≥2 browsers, once in a private window, and once with a VPN on.
3. Include **identical machines** (same model, same OS image). That is the hard case DrawnApart targets and the one that matters for an organisation.
4. Collect ≥25 same-device pairs so calibration turns on, then read the cross-browser row of *Accuracy by situation*.
5. Re-scan the same devices a week later to measure drift.

## 6. Limits and ethics

- A fingerprint links *devices*, not people. Shared and identically imaged machines, VMs, and anti-detect browsers break that link in both directions.
- Brave, Firefox (private / ETP strict), Safari 26 and Tor deliberately add noise or normalise values. The model excludes randomised features but may then lack evidence ("not enough data").
- All likelihood ratios and family caps are research estimates until calibrated on representative labelled data.
- Consent is pre-ticked in this build at the project owner's request. Any deployment beyond a controlled study needs explicit, informed consent and the legal review noted in the main research document (GDPR/ePrivacy Art. 5(3), India DPDP Rules 2025).
